Focus on three co-design mechanisms to satisfy both the 16 MB saved-activation limit and end-to-end forward + backward speed on A100:

1. **Single-pass forward statistics via linearity**: Never run `torch.cat` on `(blocks, cur)` or materialize normalized `[B+1, T, D]` tensors. Because gamma-free RMSNorm multiplies each `(s, t)` vector by a scalar inverse-RMS factor `rstd`, the scaled dot product with `queries` satisfies `sum_d((H * rstd) * q) = rstd * sum_d(H * q)`. Accumulate `sum_d(H^2)` and `sum_d(H * q)` together in one streaming pass, then stream `(blocks, cur)` once more with `probs * rstd` to write `out`.
2. **Save only O(M * B * T) scalars**: In `ctx.save_for_backward`, keep only input references `(blocks, cur, queries)` plus the compact scalar tables `(rstd, probs, logits)`, which occupy only a few megabytes instead of hundreds of megabytes.
3. **Algebraic radial reduction and fused query gradients in backward**: Compute `u = rstd * sum_d(grad_out * H)` in one streaming pass. Notice that the RMSNorm backward projection term `sum_d(dH_hat * H_hat)` simplifies algebraically to `sum_m(probs * u + d_logits * logits)`, avoiding an extra pass over `D`. Precompute the scalar per-`(t, s, m)` weights and fuse `grad_blocks`, `grad_cur`, and chunked `grad_queries` accumulation into a single pass over `(blocks, cur)`.
